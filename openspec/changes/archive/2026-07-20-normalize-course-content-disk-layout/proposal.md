## Why

The content-seed generator emits kebab-case slug URLs (`resolveSlug`/`slugify`) but reads from — and never renames — the raw on-disk folders, because the archived `filesystem-backed-course-content` design (design.md line 25) explicitly forbade touching the source layout, while the `BlobStore` contract requires kebab-case ASCII keys. Those two rules are incompatible with no bridge between them, so every `/local-filesystem-lesson/...` URL 404s and the course is unusable even with `USE_COURSE_CONTENT_SEED=1`. We resolve the contradiction by normalizing the disk to match the slug keys, and we preserve the original human names inside the generated seed so no information is lost.

## What Changes

- Add a build-time **disk-normalization step** that renames folders **and media file basenames** under `public/local-filesystem-lesson/` to their kebab-case slug form (reusing the existing `slugify`/`SLUG_OVERRIDES` logic), so the full path is URL-safe end-to-end and the seed URLs resolve against Next.js `/public`.
- **Normalize the media file basename too.** Today `discriminate-lesson.ts` builds `videoKey = ${lessonSlug}/${rawFileName}`, preserving raw `.mp4`/image names with spaces and accents. After this change the entire content key — every path segment including the file — is kebab-case ASCII, consistent with the `BlobStore` "content key MUST be URL-safe" requirement.
- **Preserve the original raw names in the generated seed** (`seed-content.ts`). The seed becomes the record of the slug→original mapping (raw folder names and raw filenames), so the pre-normalization names survive the rename and remain queryable.
- Make normalization **idempotent and safe to re-run** against an already-normalized disk (`slugify(slugify(x)) === slugify(x)`), including collision detection (two raw names slugging to the same target).
- Wire a **loud validation**: the generator calls `BlobStore.exists()` on every emitted key and fails non-zero if any key does not resolve on disk — so this class of slug↔disk drift can never silently ship again.

Non-breaking by default: `USE_COURSE_CONTENT_SEED` stays off, so normal `pnpm dev` is unaffected. The regenerated `seed-content.ts` is autogenerated and committed; the 15 GB asset tree is gitignored.

### Modified Capabilities
- `course-content-storage`: (a) the URL-safe "content key" requirement now covers the **entire** path including the media file basename (generator must slugify the filename, not preserve it); (b) a **new requirement** that the on-disk layout under `public/local-filesystem-lesson/` is normalized (renamed) to match the slug keys so URLs resolve; (c) a **new requirement** that the generated seed preserves the original pre-normalization names; (d) the generator MUST validate every emitted key via `BlobStore.exists()` and fail loudly on a miss.

## Impact

- **Assets**: `public/local-filesystem-lesson/` (15 GB, gitignored) — folders and files renamed in place. One-time, idempotent.
- **Scripts**: new rename/normalization script; `scripts/discriminate-lesson.ts` (`videoKey`/`posterKey`/`resourceKeys` now slugify the basename); `scripts/generate-course-content-seed.ts` (emit original-name data + `exists()` validation); `scripts/slug.ts`/`slug-overrides.ts` reused unchanged.
- **Seed**: `src/adapters/persistence/in-memory/seed/seed-content.ts` regenerated, plus original-name data. Whether the original names ride on the domain entities (`Course`/`Module`/`Lesson`/`Resource`) or in a separate side-map export is a design.md decision (default lean: side-map, to keep the domain free of presentation-irrelevant fields).
- **Domain**: potentially `src/domain/entities/**` IF the original name is stored on entities (deferred to design).
- **Tests**: rename-script unit tests (fixture tree, idempotency, collisions), updated `discriminate-lesson`/`slug` tests, generator `exists()`-validation test. No change to default-boot behaviour (A1 seed path stays green).
